# Checkpoint C3 — hub link on the C3 and C6 (2026-10-21)

**Covers:** roadmap checkpoint C3 ([11](../spec/11-roadmap.md)) and gates **T-LED** and **T-PRES** ([10 §10.5](../spec/10-testing.md)). Design and contracts: [docs/design/c3-hub-link.md](../design/c3-hub-link.md).

**Setup:** router `TENRETNI`, channel 1, one BSSID; hub on the MacBook over Wi-Fi (`dimas-3.local` = 192.168.0.29), TCP/UDP 7421. Boards: C3 0.42" OLED #2 `1cdbd4175cc4` → **`pad-c3`** (addr 1, profile `c3o-pad`), C6 Super Mini `58e6c5d55e64` → **`pad-c6`** (addr 2, profile `c6-pad`).

## Provisioning

| Step | `pad-c3` | `pad-c6` |
|---|---|---|
| `fr devices provision --port … --profile … --alias …` | registered, flashed with `fr_ident`, serial HELLO in time; **Wi-Fi did not join** (finding 1) | 12.1 s end to end: flash, serial HELLO, joined over Wi-Fi |
| After the TX-power fix | associated on the first attempt; got 192.168.0.31, resolved `dimas-3.local` → 192.168.0.29 by mDNS, TCP session ≈ 6.5 s after boot | — |
| Link state once online | TCP + serial sessions, UDP heartbeats, clock synced on 8 samples (RTT 9.2 ms, ±4.6 ms), RSSI −65 dBm at the desk (−77 on the charger), free heap 117 KB | TCP + serial |
| App image size (Wi-Fi, lwIP, mDNS) | 53.5 % of the 1.875 MB slot (C2: 15 %) | 59.5 % |

## Gates

**T-LED** — passed on both boards.

| Check | Result |
|---|---|
| `fr send all status.blink {count 3}` (reliable) | RESULT ok over TCP (RTT 8–30 ms), then `status.effect_done` from every device (`wait event --selector all --per-device`) |
| `status.set` with `--ack none` (fast) | sent; the hub's property mirror shows `status.on: true` |
| `status.toggle --duplicate` (the same envelope twice) | exactly one `status.on` STATE per board; node stats `dup: 1, cached_replies: 1` (the response cache answered the copy) |
| LEDs by eye | C6 RGB green and C3 blue LED set over Wi-Fi, confirmed |

**T-PRES** — passed.

| Check | Result |
|---|---|
| Unplug (C3, old hub code) | suspect at 2.52 s of silence, offline at 3.52 s after the last frame |
| Unplug (C6, final code) | serial session ends at once (`usb port gone`); suspect at 2.5 s; offline **2.76 s after the unplug** (spec: 2.4–3.5 s); back online over TCP ≈ 9 s after replugging |

| UDP blocked on the C6 with the final firmware | same; `delivery_failed: 0` |

## Also verified

- `fr diag pad-c3 info|stats` over the Wi-Fi link (`fr.diag.exec`, bulk reply) with no serial port.
- `node.describe` returns the encoded `Descriptor` (profile, board, both instances, catalog hash).
- Rename: `fr devices set pad-c3 --alias pad-c3-oled` reaches the node at once (`set_alias`), survives a reboot (`fr_ovr`), `alias_rev` 2 → 3 on the way back.
- `fr input pad-c3,pad-c6 boot double_click`: `down/up ×2 → click{2}` per board; real BOOT presses on the Wi-Fi-only C3 arrive as `down → up{366/344 ms} → click{1}`.
- `fr logs pad-c3` and `fr flash pad-c3 --plan app` take aliases.

## Findings

1. **C3 board #2 never finished WPA2 authentication at full TX power** (`init → auth → init (0x200)` in a loop: the AP never answered). The board manifest field `rf.max_tx_power_qdbm` existed but nothing applied it; `fr gen firmware` now emits `CONFIG_FR_WIFI_MAX_TX_POWER_QDBM` and `fr_net` calls `esp_wifi_set_max_tx_power()` after `esp_wifi_start()`. With 34 (8.5 dBm) the board associates on the first attempt. Board #1 joined at full power in C1, so this is a per-board RF spread, and the cap is now the C3 manifest default.
2. **A reboot RESULT lost to its own BYE.** With a serial session and a TCP session up, the BYE went out on every link and the serial copy overtook the TCP RESULT; the hub ended the session and reported the accepted reboot as `DEVICE_OFFLINE`. Now the RESULT and the deferred BYE leave on the request's link, and the hub keeps pending commands for a short grace after a BYE.
3. **Two TCP reconnects in 3.5 h** on `pad-c3` (old firmware), each back within a second, cause unknown. The node now logs every TCP close with its reason and counts closes by kind (`tcp_close_peer|keepalive|error|session|wifi`, `wifi_last_reason`) in `diag stats`; none occurred during the final runs.
4. The adversarial review confirmed 15 further issues, all fixed before the final runs. They included: Q1 retries stuck on UDP after `udp_ok` cleared; a false `udp_blocked` for unprovisioned nodes; a queued `full` flash able to erase a just-written identity; the default alias; `wait_for_event` matching pre-cursor input on a quiet hub; `drop_hub_link` not holding TCP reconnects; the provisioning temp dir surviving a hub crash; and counters.
