## What was built (brief)

Design §1–§8 list the files. As built:
- **`fr.analog_in` 1.0** (D1–D4): the capability YAML; `hal::AnalogSource` and `AnalogInService` (report rule, rate limit with a trailing report, EMA or median-of-3 filter, `crossed` with hysteresis, inject hold); driver `adc_oneshot` (ADC1 only, 12 dB, curve-fitting calibration, **8 conversions averaged per reading**: below); codegen array config, the `SERVICES` entry and the cross-field checks; profile `c3o-analog` (boot 1, status 2, analog 3 on GPIO3, thresholds 16384/32768/49152).
- **Fixture PWM setpoints** (D5): `fr.fixture` 0.2, drive `pwm` (LEDC, 20 kHz, 11-bit; duty 0..10,000 maps to 0..2,048 steps, 2,048 being fully on on LEDC) and `set_duty` (id 4) → RESULT `{at_us}`; ch12 and ch13 on `s3k-fixture`; the bench file's two analog lines `wired: true` with `rc`, and `fixture.vdd_mv` 3300; the bench validator's glitch-pin exemption for a pwm analog line with an `rc`; the hub's `fixture.setMv`.
- **Streaming STATE** (D6): a pending UDP repeat of a STATE is replaced by a newer one (diag `stats` `state_repeats_superseded`), for every STATE; the event store thins STATE of streaming capabilities only (those with a `report_hz` config, today `fr.analog_in`) to one row per property per second, the newest kept (`hub_status.events.state_thinned`); the dashboard keeps STATE out of its 2,000-event ring and draws a 120-point sparkline per property.
- **The analog input path** (D7): `input_simulate` takes exactly one of `gesture`, `value` or `mv`; `hold_ms` on inject only; the gpio layer sets a setpoint and answers `setpoint {mv, duty, vdd_mv, applied_mv, at_fix_us, at_hub_us}`; diag `inject <inst> value=<n> [hold_ms=<n>]`; the dashboard's value form.
- **The reorder buffer** (D8–D10): capability flag `ordered`, EXT TLV `0x05 port_seq` (u16, non-critical), one route (URGENT) for an ordered port's events; the hub's buffer per (device, port), 50 ms from the first held event, at most 8 held; `hub_status.router.reorder`. `fr.button` is `ordered`.
- **`vbat_mv`** (D11): the board yaml's `battery: {gpio, divider, low_mv}`, codegen's `kBattery`, the vitals' 8 conversions per heartbeat through the shared ADC1 unit. pad-s3's divider is **2.617, measured** (below).
- **Kit and gates:** the kit's per-profile port table and `WaveAnalog`; `t-analog.ts`, `t-vbat.ts`, `t2-analog-30.yaml` (`tests/sim/t2-analog.ts`); the T2 runner's fr_fleet staleness guard (below).

## Decisions taken with you, and rules still proposed

## What changed against the design

- **Event-store thinning for streaming capabilities only.** Thinning every STATE broke T-HIL's LED phase, which reads `status.on` changes back through `events_read`.
- **Superseded repeats apply to every STATE.** A toggle shorter than 20 ms whose first UDP copy is lost now repeats only the newer value.
- **Reorder reset semantics** (review fix): a same-epoch HELLO releases what is held but keeps each port's `expected`; a new epoch restarts each port at 1; a device first heard this hub run takes its first event as `expected`. Router stop flushes held events before the event store stops.
- **`adc_oneshot` averages 8 conversions per reading.** Not in the design; added after T-ANALOG run 1 (below).
- **The S3 battery divider is 2.617,** measured against a multimeter, not the ×3 taken from other Waveshare S3 boards.
- **LEDC duty** maps 0..10,000 to 0..2,048 steps (2,048 = fully on on LEDC).
- **`fr.fixture` 0.2's surface:** `set_duty` (id 4); `input_simulate` takes exactly one of gesture | value | mv, `hold_ms` on inject only; the gpio result carries `setpoint {mv, duty, vdd_mv, applied_mv, at_fix_us, at_hub_us}`.
- **T-ANALOG reads each DUT's analog config from the running build's artifact manifest** (`FR_HOME/artifacts/builds/<id>/manifest.json`); no hub op exposes instance config yet (open).
- **The T2 runner refuses a stale `fr_fleet`** (T2-ANALOG-30, below).

## The review round

**Shape:** one pass, three reviewers by area (hub and protocol, gates and spec, firmware), then two fix agents.

**Hub and protocol:** 1 major and 5 minor.
- **Major:** held events were lost at hub stop. Fixed: router stop flushes them before the event store stops.
- **Minor:** the reorder reset semantics (fixed, as above); `t_hub_us` is not monotonic per port while a node is unsynced (documented: a released event keeps its arrival stamp); the thinning counter was not reported (fixed: `hub_status.events.state_thinned`); the LEDC timer budget was overwritten (fixed); an older hub rejects `c3o-analog`'s array config (accepted: hub and firmware move in lockstep).

**Gates and spec:** 1 blocker, 1 major, 3 minor, all fixed.
- **Blocker:** T-ANALOG's inject latency compared the Mac's clock with hub µs. Now t0 = the result row's `t_hub_us` − `rtt_ms`, on the hub's clock, which the STATEs' `t_hub_us` run on.
- **Major:** T2-ANALOG's "50 Hz" streamed about 39 Hz with a 4 s sine, which stays inside the 512 deadband near its top and bottom. The period is now 1 s, and the achieved rate is published.
- **Minor:** the crossed phase's dwell nudging, with a setup-versus-chatter verdict; the vbat median wording; the config read from the manifest.

**Firmware:** 4 minor and a missing test, all fixed.
- `release_at_boot` did not take a pwm pin off LEDC on real S3 silicon (OEN_SEL); the host shim now models OEN_SEL;
- `set_battery` raced the core task;
- a 264-byte `ExtBuilder` on every EVENT;
- the release level after a failed LEDC write;
- the missing test: D10's loss path.

## Findings and open items

1. **ADC noise on the C3 with Wi-Fi on** is 25–60 mV p-p for a single conversion at 1.2 V: more than the default deadband (19.5 mV) and hysteresis band (39 mV). Averaging 8 conversions brought p10–p90 to about 10 mV. Any `fr.analog_in` driver on a radio board needs the same, or a wider deadband.
2. **pad-s3's divider is 2.617, not ×3.** Measured once, with no cell; T-VBAT is circular until a cell is fitted.
3. **T-HIL's 5 % resync limit in the LED phase is fragile:** one S3 resync (3 STATEs of 52) is 5.77 %. Open; not a rule change.
4. **30 nodes at 50 Hz** reached `planning_pct` 35.91 % on the AP model, over C2's 35 % rule; 20 Hz gave 23.52 %. Model output until S2 calibrates it.
5. **A stale `fr_fleet` ran silently** once. The runner now refuses it.
6. **Proposed rules awaiting your approval:** the T-ANALOG pass numbers; `report_hz` 20 and `deadband` 512 as provisional defaults (approved 2026-10-28 after S2); streaming STATE thinned to 1 row/s per property; T-VBAT's median rule.
7. **Two hub restarts** in this checkpoint (REGISTRY_HASH changed twice), against the one-restart rule of 11 §11.6.
