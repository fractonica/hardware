# C5 ESP-NOW: implementation design

> **Folded into the spec on 2026-10-22:** the §8 decisions (1–24) and the contracts of §2–§7 now live in [docs/spec](../spec/README.md) (mainly 05, 07 and 09; also 02, 03, 06, 08, 10 and 11), and C5's open items for later checkpoints are listed in [11 §11.4](../spec/11-roadmap.md). This note is kept as the implementation record.

Checkpoint C5 ([11 §11.4](../spec/11-roadmap.md)): ESP-NOW unicast, bindings, flood seeding. Gates **T-NN**, **T-FLOOD**, **T-FLOOD-B** ([05 §5.18](../spec/05-network.md)).

Source of truth: spec 05 §5.3–5.5 (radio, channel, addressing), §5.8 (delivery, windows, Q1), §5.9 (managed flooding), §5.10 (link selection, directory, node ↔ node), §5.11 (presence), 07 §7.11 (bindings), 09 §9.4 (`message_send`, `binding_*`, `latency_stats`) and §9.7 (diag), 10 §10.3 (fake links). This note fixes what the streams share and decides what the spec leaves open; §8 lists the decisions to fold back. Sections 2–5 describe C5 as built (the streams' choices reconciled by the integrator, then the review fixes and the first bench runs of T-FLOOD and T-FLOOD-B); fold §8 into the spec when T-NN, T-FLOOD and T-FLOOD-B pass on target.

## 1. Scope

In:
- **Node:** an ESP-NOW link (`esp_now` on the STA interface, robust 1 Mbps rate, broadcast peer + LRU unicast peers, one send in flight, three priority queues, link retries); node ↔ node windows; managed flooding (relay queue, jitter, K suppression, TTL, seeding from the hub over TCP/serial); node-originated broadcasts (ESP-NOW and the hub); node → node unicast with the fallback chain (ESP-NOW → via hub → flooded unicast); Q1 on ESP-NOW hops; the router-mode ESP-NOW heartbeat and a neighbour table; the directory (NET/DIRECTORY, `nvs:fr_dir`, RESOLVE); MSG (`fr::msg::send/on`); bindings (`fr.node.bind_set/clear/list`, `nvs:fr_bind`, execution after the triggering event, `node.binding_fired`); the broadcast watermark in HEARTBEAT; `ota_busy` stops relaying.
- **Hub:** hub broadcasts (BCAST counter, fan-out over every node link, `valid_ms`, watermark repair, the flood rate); node-originated broadcasts (deliver as `msg` events, fan out with `ttl_remaining = 1`); forwarding node → node frames; DIRECTORY on every registry change and RESOLVE answers; `message_send` (with `count`/`interval_ms` for test bursts); `binding_set|list|clear` (resolve, validate, pre-encode, push, re-push); `latency_stats`; events `msg` and `node.binding_fired`.
- **Gates:** T-NN, T-FLOOD, T-FLOOD-B.

Out: gateway mode (M2), groups (M2), fragmentation over ESP-NOW (frames > 250 B stay off the air), ESP-NOW encryption (never), the fast rate profile (`game`, later), adoption over the link (M2), proxying through a neighbour (M2), scheduled execution of node → node CMDs (`exec_at` answers UNSUPPORTED until T-LAT).

## 2. Wire (foundation)

- **`LinkKind::espnow = 3`.** ESP-NOW payload = one envelope, ≤ 250 B (realtime MTU); a BULK frame never goes on the air.
- **Binding types** (protocol `types:` in `schema/protocol.yaml`; `Binding.kMaxSize` 169, `BindingList` ≤ 2752 B):

```yaml
Binding:
  slot:      { id: 1, type: u8, range: [0, 15] }
  on_port:   { id: 2, type: u8 }
  on_cls:    { id: 3, type: u8 }            # 3 EVENT | 7 MSG
  on_kind:   { id: 4, type: u8 }            # event id (EVENT)
  on_topic:  { id: 5, type: string, max: 32 }   # MSG topic
  to_mac:    { id: 6, type: bytes, max: 6 } # empty for a broadcast target
  to_addr:   { id: 7, type: u16 }           # self, a node, or 0xFFFF (MSG broadcast)
  to_port:   { id: 8, type: u8 }
  to_cls:    { id: 9, type: u8 }            # 4 CMD | 7 MSG
  to_kind:   { id: 10, type: u8 }           # command id (CMD)
  to_topic:  { id: 11, type: string, max: 32 }
  payload:   { id: 12, type: bytes, max: 64 }   # pre-encoded CMD fields (generated defaults included) or MSG data
  reliable:  { id: 13, type: bool }
BindingList: { items: { id: 1, type: "array<Binding>", max: 16 } }
```

  `fr.node.bind_set` takes the `Binding` fields flat as its args (same ids, so its args are an encoded Binding; the vector emitter checks it); `bind_list` returns `{bindings: bytes ≤ 1400}` holding an encoded `BindingList` (BULK, so TCP or serial; 1400 is what a bulk RESULT carries, `fr::net::kBindListMax`). A legal `BindingList` reaches 2752 B, so `bind_set` answers INVALID_ARGS when the table with the new binding would encode past 1400 B (each item `1 + varint(len) + len`, the slot's old bytes excluded): `bind_list` then always carries the whole table (FAILED only for a table an older firmware stored). With 32 B topics and 64 B payloads, 9 MSG → MSG bindings fit; typical ones of 30–60 B all 16. `bind_clear {slot}` (255 = all). `node.binding_fired {slot, target_status, rtt_us, path}`: `path` 0 espnow, 1 hub, 2 flood, **3 local** (the binding's target is the node itself).
- **diag:** `neighbors [from]` (the neighbour table, sorted by MAC, paged like `caps`: `{count, neighbors: [{mac, addr, rssi, age_ms, ack_ok, ack_fail}], next?}`), `net wifi_down <s>` (debug: disconnect the STA and do not reconnect for s seconds, keeping the radio on channel C; T-FLOOD-B without powering the router off), `info` gains `links.espnow {up, ch, peers}` and `hooks.wifi_down{,_s}`. `stats` gains `espnow: {tx, tx_fail, retries, refused, rx, rx_bad, rx_lost, peers, rate_fail?, guard?, lost?}` (the driver's frames on the air; Net's view stays in `links.espnow`; `guard` and `lost`, shown once a send callback missed the guard, count the sends whose callback came after 100 ms and those with none within 1 s), `relay: {seeded, relayed, cancelled, dropped}`, `nodes: {delivered, dup, old, sent, via_espnow, via_hub, via_flood, failed, resolves}`, `bcast: {delivered, dup, old, watermark}`, `bindings: {fired, failed, rtt_p50_us}`, `msgs: {<topic>: n, other}` (≤ 8 topics). A full answer that would not fit its channel (fr.diag.exec's 1,400 B) first folds `msgs` into `{other}` (`msgs_folded`), then drops whole sections (msgs, nodes, bindings, espnow, relay, bcast, links, in that order), naming them in `omitted`; `stats <section>` answers one section alone.
- **Golden vectors** for `Binding`, `BindingList`, `fr.node.bind_*` and the flooded envelopes (`msg.flood_hub_seed`, `msg.flood_relayed`, `msg.flood_repair`, `msg.flood_node_origin`, `cmd.node_bind_set`).

## 3. Node

**Core** (`fr_net/src/core`, host-buildable: `air.cpp` receive side, flooding, directory, heartbeat; `peer.cpp` node ↔ node sends and answers; `bindings.cpp`):

```cpp

using Mac = std::array<uint8_t, 6>;
enum class AirPrio : uint8_t { urgent, normal, bulk };
struct RxMeta { Mac src_mac; bool to_broadcast; int8_t rssi; uint8_t channel; };   // ESP-NOW receive info
class AirLink {          // the ESP-NOW driver (fr_net/src/esp/espnow.cpp; fr_net_node's fake medium)
 public:
  virtual bool up() const = 0;   // started and channel C known
  virtual Status send(const Mac &dst, std::span<const uint8_t> env, AirPrio prio, uint32_t token) = 0;
  // busy only for a full queue or a peer table whose every slot was used within 1 s; completion comes back
  // as Net::air_sent(token, mac_acked) on the core task
};
enum class Delivery : uint8_t { fast, reliable };
enum class Path : uint8_t { espnow = 0, hub = 1, flood = 2, local = 3 };
// Net gains: attach_air(AirLink&), attach_stores(DirectoryStore*, BindingStore*), receive_air(env, RxMeta),
// air_sent(token, ok), send_to_node(addr, cls, kind, port, body, Delivery), broadcast(cls, kind, port, body,
// ttl = 0 /* FR_TTL_DEFAULT */), send_msg(dst, topic, data, Delivery), set_binding(encoded) / clear_binding(slot) /
// encode_bindings(out), bindings(), directory(), neighbors(), msg_stats(), set_relay(RelayConfig),
// wifi_up_neighbor_heard_at() (the STA's sweep rule).
// Host gains msg(src, topic, data) (default no-op). State gains relay, bcast, bindings and nodes stats.
}
```

- **Windows** (05 §5.8): node-originated frames → per `(src, epoch)` 128-bit window, up to 64 sources (LRU); a lower epoch drops, a higher one resets; LATEST frames keep the newest per source. A source new to this node (first heard, or evicted by the LRU) starts with everything below its first ordinary frame presumed received, and those seqs are OLD, not DUP: never delivered, ACKed or answered from the cache, so a sender whose earlier reliable frame that first frame overtook ends FAILED instead of getting an ACK for a frame nobody ran. A newer epoch of a known source starts with an empty window instead, so frames of the new boot that its first frame overtook are still delivered. Hub frames keep their C3 windows; hub broadcasts heard over ESP-NOW use the hub BCAST window of this boot's last WELCOME (also after that session ended; none before any WELCOME), shared with the hub link's copies. A WELCOME of the hub run the window already follows (same non-zero `hub_epoch`: a Wi-Fi node reconnecting while broadcasts run) only raises its floor to `bcast_base`, never moving it back, so a broadcast above the base that came over the air or the other session first is not delivered again when the hub's copy follows; a WELCOME of another run resets it to the base. The unicast window, LATEST state and floors reset on every WELCOME. DUP of a request → cached response. The receive filter takes only this node's `net`, drops its own frames, a TTL above `ttl_max` and BULK frames; an unprovisioned node ignores ESP-NOW. Node frames over TCP or serial are taken only inside a session and only with `ttl_remaining < ttl_initial` (the hub's forward takes one off, its fan-out sets 1).
- **Flooding** exactly as 05 §5.9: `from_air` (ESP-NOW to the broadcast MAC) and `from_hub` (TCP/serial, `src = 0x0000`, flood `dst`) seed a relay with `ttl_remaining − 1`, `RELAYED = 1`, delay `uniform(1, 16) ms (+ RSSI bias when from_air: −30 dBm → +8 ms, −90 → +0, linear)`; K = 2 copies **heard over ESP-NOW** cancel it, and a seed starts at 0 copies like a relay. A copy on a hub link (TCP or serial) never counts and never re-seeds: the seed's own copy, a repair, the other session's duplicate of the same broadcast, the hub's fan-out of a node broadcast. None of them says what the neighbours heard. (The first build counted the hub link's copy as one; on the bench, T-FLOOD then went on the air about once per broadcast, 1.24 transmissions with two hub-linked seeders, and the node with no hub link got 994/1000.) Two seeders in range of each other therefore both transmit (≈ 2 transmissions per broadcast with three nodes, and a node with no hub link misses one only when it loses both copies, ≈ PER²); suppression acts from three seeders up. K = 0 relays nothing. Repairs and fan-outs (`ttl_remaining` 1) are never re-seeded; `relay_enabled` (default on), `!ota_busy` and not a gateway; relays go to the broadcast MAC; a relay queue of 8. Each source is metered at 10 floods/s (token bucket, burst 10, 8 sources LRU, taken at transmit time; TTL-1 frames exempt); an own broadcast over the rate goes to the hub only. A flooded unicast (broadcast MAC, `dst` = node): the target delivers and does not relay.
- **Node-originated broadcast / MSG to 0xFFFF:** ESP-NOW broadcast with `ttl = 2` **and** the same bytes to the hub (TCP/UDP or serial per 05 §5.10). Never ACKed.
- **Node → node** (05 §5.10): MAC from the binding, the directory, else the neighbour table → ESP-NOW unicast (the MAC ACK confirms the hop); after the link retries (2 ms, 4 ms) fail, or without a MAC (a RESOLVE asks the hub) → via the hub if a hub session is up → else a flooded unicast (broadcast MAC, TTL 2). If the driver answers busy (peer table in recent use), a TTL-1 broadcast instead. Answers (RESULT, ACK) take the same chain starting at the source MAC when the request came unrelayed. An accepted send with no completion within 250 ms counts as a failed hop; an answer that overtakes the completion counts the hop as ESP-NOW. A fast frame that no path took (the unicast and the TTL-1 broadcast refused, no hub session, the flooded unicast refused or over the flood rate) is dropped, counted in `nodes.failed`, and `send_to_node` / `send_msg` / `fr::msg::send` answer BUSY; a reliable frame answers OK and is retried; a binding's frame is reported only through `node.binding_fired` (`target_status` BUSY), never as a second failure.
- **Q1 on ESP-NOW:** reliable CMDs and Q1 EVENT/MSG carry ACK_REQ; the target answers RESULT (CMD) or ACK (EVENT, MSG); end-to-end retries `(20 ms + 10 ms × hops) × 2^(n−1) ± 25 %` (hops 0 for an ESP-NOW unicast or TTL-1 flood, 1 via the hub or a flooded unicast; the timer restarts when a hop falls back), 4 attempts, same seq; 8 node → node frames in flight (the oldest evicted). Broadcasts are never ACKed (watermark repair instead). `exec_at` answers UNSUPPORTED; `expire_at` is not checked (another node cannot compute hub-synced time).
- **ESP-NOW heartbeat** every 5 s ±20 % (`PRESENCE/HEARTBEAT`, the hub heartbeat's fields, `dst 0xFFFF`, TTL 1, LATEST, never relayed, never to the hub; the first at a random point within one interval after the air comes up); the neighbour table (≤ 20: MAC, addr, RSSI, last heard, MAC-ACK ok/fail counts) learns only from `RELAYED = 0 && ttl_remaining == ttl_initial` frames. The jitter generator is seeded from the factory MAC once it is known (never from an all-zero one). A fresh heartbeat heard over the air whose `state` has `wifi_up` stamps `Net::wifi_up_neighbor_heard_at()` (core clock; 0 = never): that neighbour is associated, so an AP of the network is on C. fr_core hands it to the driver as `AirHooks.wifi_up_heard_at`; the driver copies it into an atomic uptime-seconds stamp after each received batch, which the STA's sweep rule reads.
- **Directory:** a NET/DIRECTORY page is classified by its content, whatever RESOLVE is outstanding. A lone page 0 of 1 holding one entry whose addr is not the node's own is a RESOLVE answer: it merges into the table and leaves a set being staged alone. A lone page 0 of 1 with no entries is the "unknown" answer and changes nothing. Anything else is part of a page set (page 0 starts one; ≤ 32 pages), which replaces the table once complete, and only if one of its entries is the node's own addr (checked on the raw entries, so also past the 64 kept): the hub's sets list every provisioned device, the asker included, so a set that does not is no directory. An unchanged set is not saved again; the table is persisted to `nvs:fr_dir` (≤ 64 entries, written on `fr_worker`). RESOLVE `{addr}` when an addr is missing (with a hub session), at most once per second per addr over the last 4 addrs asked (when all 4 are in use, the one asked longest ago is reused; an entry is freed when its answer merges). (The first build tracked one RESOLVE and took an answer for any other addr as a whole set, wiping the table and NVS.)
- **Broadcast watermark:** the highest hub BCAST seq such that every earlier one in the window was received; HEARTBEAT `bcast_watermark`; starts at WELCOME `bcast_base`.
- **Bindings** (07 §7.11): ≤ 16 in `nvs:fr_bind`, whose encoded `BindingList` stays ≤ 1400 B (`set_binding` answers INVALID_ARGS past it, §2); on a local EVENT emission (`Net::event`, before the hub send: fr_core's sink is Net, so that is the local event hook; fr.node's own events on port 0, `boot` and `binding_fired`, are sent by Net outside `Net::event` and trigger nothing, so the hub refuses such a binding) or a received MSG topic, each matching binding sends its pre-encoded CMD/MSG to `to_addr` (self → local dispatch with its own reply buffer, 0xFFFF → MSG broadcast, a node → node path above starting at the binding's MAC, so it works with the hub stopped). Binding CMDs carry URGENT. A binding's reaction may fire bindings again up to depth 2. Then `node.binding_fired {slot, target_status, rtt_us, path}`, held until the triggering EVENT has gone to the hub: `rtt_us` from the fire to the target's RESULT (reliable), 0 for fast; `target_status` the RESULT/ACK status, 0 for fast/MSG/broadcast, FAILED after the last attempt, BUSY with no path or when evicted, INVALID_ARGS for a group target or a CMD broadcast off port 0. Bindings work with no hub session.
- **MSG** (`fr/msg.hpp`): `fr::msg::send(dst, topic, data | text, reliable = false)` through `Net::send_msg`: another node, `kBroadcast`, `kHub` (0x0000, a `msg` event; Q1 like an EVENT when reliable) or the node itself (its bindings and handlers, nothing sent); a group is INVALID_ARGS. `fr::msg::on(topic, handler)`: ≤ 8 handlers, exact topic, called after the bindings on that topic. Core task only.
- **ESP-NOW driver** (`fr_net/src/esp/espnow.cpp`, send discipline in the IDF-free `air_sched.hpp`): `esp_now_init` after `esp_wifi_start`; broadcast peer added at init; unicast peers LRU (≤ 17; a peer used within 1 s is never evicted: `send` answers busy); `esp_now_set_peer_rate_config` after **every** `add_peer` with `{.phymode = WIFI_PHY_MODE_11B, .rate = WIFI_PHY_RATE_1M_L}` (never a zero `phymode`; a failure counts `rate_fail`); peer channel 0; one send in flight; queues URGENT > NORMAL > BULK, 16 frames with 4 kept for URGENT; link retries 2 ms then 4 ms (`esp_timer`), broadcasts included; a 100 ms guard for a late send callback, which fails that attempt but leaves its callback owed: no other send (its retry or the next frame) goes out until that verdict arrives or 1 s after the send (`kSendLostUs`, then the callback is taken as lost), so the driver never holds two of our sends and a late verdict is never credited to another frame (the send callback counts verdicts and keeps the last one's status; `Scheduler::sent(n, last_ok, now)` matches them to sends by count and order, and a late verdict that arrives while a send is held only releases it, the guard having counted its attempt already; frames held behind it can pass Net's 250 ms completion and fall back, and windows drop the later air copies; counters `guard`, `lost`); callbacks copy into a 16-slot receive ring and post to the core task; receive filter: channel C, magic/version, `net`, length 18..250. `up()` once started and channel C is known (a usable pin, else the first association). HELLO `caps` gains `espnow_v2`.
- **Channel C and `net wifi_down <s>`:** the STA tracks C and keeps an idle, disconnected radio on it (`esp_wifi_set_channel`). Where a node that lost its AP looks is `search()` in the IDF-free `sta_rules.hpp` (host-tested): with no usable pin, a join by SSID on every channel; otherwise a 30 ms active scan of C for the pinned BSSID, except that (a) while a neighbour heartbeat reporting `wifi_up` was heard within 60 s it never sweeps (an AP of the network is on C), and after 60 s without the pinned BSSID, when fr_ident names no BSSID, the scan of C takes any AP of the SSID (the pinned one first, records whose primary channel is not C ignored, the strongest joined and re-pinned: a replaced router, a mesh node switched off); (b) otherwise, while any ESP-NOW frame was heard within 60 s (neighbours on C, none of them on Wi-Fi: the router is off or moved), it sweeps all channels after 5 min without the AP, then every 5 min; (c) alone, after 60 s, then every 60 s. A 120 s router outage (T-FLOOD-B) therefore never takes a node, and ESP-NOW with it, off C, and a router that came back on another channel is still found within 5 min. (The first build suppressed the sweep while any ESP-NOW frame was heard: nodes that all lost the AP kept each other from sweeping for ever.) A boot or the end of a `wifi_down` hold restarts the wait; only sweeps from a usable pin count toward HEARTBEAT `swept`. **Pins** (`Pins` in `sta_rules.hpp`): `nvs:fr_link`'s pin is the base network's; a `net_set` trial's association pins the trial in RAM only, written to `fr_link` once the trial is confirmed (GOT_IP), so a reverted trial leaves `fr_link` as it was. C follows `Pins::home()`: the usable pin's channel (the associated AP's while associated); during a trial the pre-trial network's C until the trial associates, then the trial AP's (also after a reboot during a trial); after a revert the base pin's channel, or 0 (ESP-NOW down) when that pin is unusable; `HOME_CHANNEL_CHANGE` moves C whenever associated and re-pins the live pin. `wifi_down` is applied ~300 ms after its RESULT, disconnects and holds the STA (no join, no scan, trial revert paused), keeps the radio on C; 0 ends it; a new request extends it.
- **NVS:** namespaces `fr_dir` and `fr_bind`, key `table`, blobs `ver=1 | count | entries`, decoded in place, written on `fr_worker` (two buffers, newest wins, an identical table skipped, retried when a queue was full).

## 4. Hub

- **Hub broadcasts** (`message_send {to: "broadcast"}` and future broadcasts): one BCAST seq per broadcast (no gaps), `dst = 0xFFFF`, `ttl` 2/2, EXT `valid_ms` 2000; the same envelope bytes to every welcomed session of each node, TCP **and** serial (a standby serial session included: the one exception to "nothing else takes a standby serial session"). The node's BCAST window delivers it once and seeds from the first copy; the other session's copy is a DUP that neither seeds nor counts toward K. (The first build sent it over the node's best session only: a dual-link node whose Wi-Fi died without a FIN kept getting broadcasts on its dead TCP for about two heartbeat intervals, and the repairs that followed carry `ttl_remaining` 1 and are never seeded, so on the bench T-FLOOD-B the Wi-Fi-only node missed 3 of 115.) `BroadcastSent.sessions` and `message_send`'s `sessions` / `sessions_max` count nodes (a node on two links counts once). Nodes that get it from the hub seed the ESP-NOW flood. The flood rate (10/s, token bucket with burst 8): the excess goes over the hub links only (every session, as above) with `ttl` 2/1, so nobody seeds it (`seeded: false`, counted `bcast_tcp_only`, the name of when it went over TCP alone). The burst is what a node's relay queue (8) holds: a hub-linked node takes a back-to-back run in one read and seeds a relay for each, and a longer run would have it drop the rest, which a node with no hub link then never hears (within the nodes' own meter, 10/s with burst 10, too).
- **Watermark repair:** on every HEARTBEAT, every unexpired broadcast above `max(bcast_watermark, the WELCOME's bcast_base)` older than 250 ms goes again as the original bytes with only `ttl_remaining = 1` over every welcomed session of that node, TCP and serial (never re-seeded), at most twice per device and half a heartbeat apart, a round over both sessions counting once (the node drops the ones it has as DUP).
- **Node-originated broadcasts:** delivered as events (`msg {topic, data, dst}` for MSG; data parsed as UTF-8 JSON, else hex) and, when `ttl_remaining > 1`, fanned out by the router to every **other** node with `ttl_remaining = 1`, over that node's best session only (those copies are never seeded, so a dead TCP costs at most that node's own copy; every session would be consistent with hub broadcasts, later).
- **Forwarding:** a node → node envelope that reaches the hub (dst a node addr; TCP, UDP or serial) is checked against its sender's window and forwarded unchanged over the target's session with `ttl_remaining − 1`; `ttl_remaining` 0 or no session to the target drops it (counters `forward_ttl`, `forward_no_route`). A DUP is forwarded again (a retried request reaches the target's response cache), except within 20 ms of the last forward (the UDP/TCP twin). The hub never ACKs or answers frames meant for another node. The router does this work itself; `RouterHooks.forward` and `nodeBroadcast` observe it afterwards.
- **DIRECTORY** pages (sorted by addr, so a rename is no change) go to every welcomed session when they differ from the last ones sent: on `device.provisioned`, on every HELLO, and from a check every second. A set always lists every provisioned device, the receiving node included, and every session gets the whole set, never a filtered one: a node takes a set that does not list it for no directory (§3). **RESOLVE** `{addr}` is answered with a one-entry DIRECTORY (page 0 of 1) to the asker for a provisioned addr, and not at all for an unknown one.
- **Unicast MSG** (`message_send {to: <selector>}`): MSG on port 0 with ACK_REQ over the device's best session; the node's ACK frame answers it (2 s). A node's MSG to the hub with ACK_REQ is ACKed and published as a `msg` event.
- **Ops** (`packages/protocol/src/ops/net.ts`, handlers `packages/hub/src/bindings/*`, `packages/hub/src/router/*`):
  - `message_send {to: "broadcast" | selector, topic, data?: JSON, count = 1 (≤ 10000), interval_ms = 100 (20..60000), wait_s?}` → immediate result for one send (`{seq, sessions, seeded}` for a broadcast, per-device ACK outcomes for unicasts); a job of kind `msg` when `count > 1` (progress = sent; paced against an anchor so timer lateness does not stretch the run, and a stall longer than one interval moves the anchor to now rather than catching up in a burst beyond the flood rate; result `{sent, seeded, tcp_only, no_session, first_seq, last_seq, sessions_max, duration_ms}`). A broadcast with no node session, or unicasts to only offline devices, are DEVICE_OFFLINE.
  - `binding_set {from, to, args?}` per 07 §7.11 and 09 §9.4: resolve aliases (`broadcast` reserved), the source instance/event (or `msg:<topic>`), the target device MAC/addr/port/command (or MSG topic); both ends need an addr; the trigger cannot be an fr.node event (the `node` instance, port 0: `boot`, `binding_fired` never run bindings on the node, §3), INVALID_ARGS `<alias>.node: fr.node events (boot, binding_fired) cannot trigger a binding; bind a capability event or a MSG topic`; validate `args` against the command's JSON Schema, pre-encode the payload with the generated defaults (≤ 64 B; MSG data as compact JSON); `reliable` for a reliable command and a unicast MSG. A string given for `args` or MSG data (CLI or REST) is JSON text, and the registry keeps the text it was given (`args` column), which re-resolution parses again, so a JSON string stays a string however often a row is re-resolved (the first build stored the parsed value and parsed it again: `'"on"'` then no longer resolved, `'"42"'` became the number 42, and `null` became no data). Rows an older build stored with SQL NULL for MSG data `null` cannot be told from no data. MSG data `null` is stored as the text `null` (payload `null`), distinct from no data (empty payload); `binding_list` shows `args: null` for both, the payload tells them apart. The slot is the one already holding the same trigger and reaction (`replaced: true`), else the lowest free (a 17th is INVALID_ARGS). A binding that would make the source's encoded `BindingList` larger than `fr.node.bind_list`'s 1400 B (read from the generated catalog), measured on the registry rows with the new binding in its slot, is INVALID_ARGS whether the source is online or not (the node checks the same, §2). Push `fr.node.bind_set` to the source: UNSUPPORTED/NOT_FOUND → CAPABILITY_UNSUPPORTED, INVALID_ARGS → INVALID_ARGS (nothing stored); offline, timeout, BUSY or FAILED → the row is stored with `pushed_at` NULL and a `pending` reason. Table `bindings (device_id, slot, from_spec, to_spec, target_id, args, binding hex, pushed_at)`, index on `target_id`.
  - Re-push: on every handshake the service compares the node's `bind_list` with the registry rows (re-resolved at both ends), first clears slots the registry lacks, then re-sets missing or different slots (clearing first, so the rows always fit the node's 1400 B check; the registry wins, also over bindings another hub db put there). When `bind_list` cannot be read for any reason but CAPABILITY_UNSUPPORTED or DEVICE_OFFLINE (FAILED for an oversized table, a timeout, a table that does not decode), the registry wins blindly: `bind_clear` every slot without a row (255 when there are none), then `bind_set` every row, pushed or not, stopping at the first push that does not go through (a dead link costs one timeout; the next handshake starts over). That also carries a `fr bind rm` made while the device was offline. A new addr or descriptor re-pushes when the encoded bytes change; a rename rewrites the rows' from/to text only (the bytes carry no alias); a row that no longer resolves (a stored fr.node trigger included) stays as the node has it, with one `hub.warning {code: binding_unresolved}`.
  - `binding_list {selector?, live = false}` (registry rows; `--live` each node's `bind_list` against them: same / differs / absent, plus missing slots), `binding_clear {device, slot: 0..15 | "all"}` (rows now; the node now, or at its next handshake).
  - `latency_stats {selector?, window_s = 60 (≤ 3600)}` → per device: PING RTT p50/p99 per link (the TIME bursts and PONGs the router takes anyway; nothing probes), input → hub p50/p99 (capability ports 1–239 on a synced clock, replays skipped), binding trigger → target RESULT p50/p99 per path from `node.binding_fired.rtt_us` (`espnow`, `hub`, `flood`, `local`; rtt 0 counted as `fast`, target_status ≠ 0 as `failed`), the hub's event-loop delay (a 20 ms timer's lateness per second). In memory only: a hub restart forgets the samples.
- **CLI:** `fr msg <sel|broadcast> <topic> [json] [--count N --interval-ms M]`, `fr bind <from> <to> [json]`, `fr bind ls [sel] [--live]`, `fr bind rm <dev> <slot|all>`, `fr latency [sel] [--window 60]`, each with a one-line or table rendering (a single broadcast: `broadcast <topic> seq N to K node(s); …`).

## 8. Decisions to fold into the spec

1. `Binding`/`BindingList` wire types (slot range 0..15); `bind_set` flat args (an encoded Binding); `bind_list` returns `bytes ≤ 1400`, which the table always fits (17); `bind_clear 255` = all; `binding_fired` path 3 `local` and the `target_status` / `rtt_us` semantics of §3.
2. RSSI bias formula for relay delay; only ESP-NOW copies count toward K (14); the flood rate as a per-source token bucket (10/s; burst 10 at the nodes, 8 at the hub so a back-to-back run fits a node's relay queue); RelayStats.dropped excludes a spent TTL.
3. `message_send` flat `count` / `interval_ms` (job of kind `msg` when count > 1, no catch-up burst after a stall; `seeded`/`tcp_only` in the results); `latency_stats.window_s ≤ 3600`; `binding_clear.slot` as text; `--window` for `window_s`.
4. `net wifi_down <s>` hook (applied after its RESULT, extends, 0 ends); `diag neighbors [from]` (paged); `info` `links.espnow` and `hooks.wifi_down`; the `stats` additions (`espnow`, `relay`, `nodes`, `bcast`, `bindings`, `msgs`), the fit rule (`msgs_folded`, `omitted`) and `stats <section>` — 09 §9.7's "worst-case `stats` answer is about 1.2 KB" no longer holds.
5. Peer LRU eviction rule (a peer used within 1 s → the driver answers busy → a TTL-1 broadcast); the driver limits of §3 (queue 16 with 4 URGENT, guard 100 ms, broadcast link retries); `AirLink::up()` needs channel C; the receive filter compares with C; the sweep rule (16) and the late send callback (20).
6. Hub re-pushes bindings at every handshake when the node's list differs, the registry winning (stray slots cleared first, and a blind overwrite when the list cannot be read: 17); a rename rewrites text only; same trigger and reaction reuse their slot; push outcomes (refused vs pending); `binding_unresolved` warning; the `bindings` table columns.
7. Node acceptance rules: node frames over TCP/serial only in a session with `ttl_remaining < ttl_initial`; an unprovisioned node ignores ESP-NOW; hub broadcasts over ESP-NOW only for the last WELCOME's hub run (a hub restarted during a router outage is heard over ESP-NOW only after the node's next WELCOME); a same-run WELCOME only raises the BCAST floor (19); a new source's floor and a newer epoch's window (21).
8. Directory: page sets replace the table only once complete, and only when they list the node itself; a lone page is classified by content (18); the hub answers RESOLVE only for a known addr and the node ignores an empty answer; pages sorted by addr, sent on every change, to every session, each set listing every provisioned device.
9. Q1 over ESP-NOW timing (§3), answers' path chain, `exec_at` UNSUPPORTED and no `expire_at` check for node → node CMDs, MAC lookup falling back to the neighbour table, the 250 ms send-completion rule, binding CMDs URGENT, the binding chain depth 2; a fast frame with no path is BUSY (22).
10. Forwarding semantics (DUPs forwarded again except within 20 ms, never ACKed by the hub, counters); watermark repair semantics (everything above `max(watermark, bcast_base)`, grace 250 ms, ≤ 2 per device, over every session of the node: 15).
11. MSG API (`fr::msg::send` to a node, `kBroadcast`, `kHub` or self; `on` ≤ 8 handlers; 03 §3.2), MSG data as compact JSON from the hub, the `msg` event's `dst`; unicast hub MSGs ACKed by an ACK frame.
12. NVS layout of `fr_dir` / `fr_bind`; Kconfig ranges of §7; HELLO `espnow_v2`; the jitter seed from a known MAC only.
13. Error code list unchanged (the foundation's placeholder `NOT_IMPLEMENTED` is gone).

Decisions from the review fixes and the first bench runs of T-FLOOD and T-FLOOD-B:

14. **K counts air copies only** (05 §5.9 pseudo-code and its K row, 02's flooding line): a seed from a hub link starts at `copies = 0` (not `from_hub ? 1 : 0`); in the DUP branch only a copy with `rx.link == ESPNOW` increments `copies`; a copy on a hub link (TCP or serial) never counts and never re-seeds: the seed's own copy, repairs, the other session's duplicate, the hub's fan-out of node broadcasts. Two hub-linked seeders in range of each other both transmit (≈ 2 transmissions per broadcast with three nodes; T-FLOOD's ≤ 3 holds), suppression acts from three seeders up, and a node with no hub link misses a broadcast ≈ PER² of the time. K = 0 relays nothing. Bench evidence for the change: with the hub copy counting one, T-FLOOD went on the air 1.24 times per broadcast and the cut-off node got 994/1000.
15. **Hub broadcasts on every session** (05 N4 and §5.9; design §4): a hub broadcast goes as the same bytes to every welcomed session of each node, TCP and serial, a standby serial session included; 05 §5.10's "while TCP carries, nothing else takes a standby serial session but the answers to requests that came over it" gains this exception (hub broadcasts and their repairs). The node delivers it once; the other session's copy is a DUP that neither seeds nor counts toward K. Watermark repairs go the same way, a round counted once against the repair limit and spacing. `BroadcastSent.sessions` and `message_send`'s `sessions` / `sessions_max` count nodes. Node-broadcast fan-out (`ttl_remaining` 1) stays on each node's best session. Bench evidence: T-FLOOD-B with `wifi_down` on all three, the USB nodes' broadcasts went to their dead TCP for over two intervals and the repairs that followed (TTL 1) were never seeded; pad-c3 got 112/115.
16. **Sweep cap and pins** (05 §5.4, replacing "≥ 60 s with no ESP-NOW neighbour heard"): (a) a neighbour heartbeat on C reporting `wifi_up` heard within 60 s: never sweep; after 60 s without the pinned BSSID, and only when fr_ident names no BSSID, the 30 ms active scan of C looks for any AP of the SSID (the pinned BSSID first, records whose primary channel is not C ignored), joins the strongest and re-pins; (b) otherwise, any ESP-NOW frame heard within 60 s: sweep after 5 min without the AP, then every 5 min; (c) otherwise after 60 s, then every 60 s. A boot or the end of a `wifi_down` hold restarts the wait; only sweeps from a usable pin count toward HEARTBEAT `swept`. Pin persistence "after every successful association" gains one exception: a `net_set` trial's association is pinned in RAM and written to `nvs:fr_link` only when the trial is confirmed (GOT_IP), so a reverted trial leaves `fr_link` as it was. Channel C follows the live pin: the usable pin's channel (the AP's while associated); during a trial the pre-trial C until the trial associates, then the trial AP's (also across a reboot during a trial); after a revert the base pin's, or 0 (ESP-NOW down) when it is unusable; `HOME_CHANNEL_CHANGE` moves C whenever associated and re-pins the live pin. Residual: credentials that name a BSSID which moved channel while a neighbour is on Wi-Fi through another AP of the SSID are not swept for (rule a).
17. **`bind_list` 1400 B cap** (07 §7.11, 09 §9.4, `node.cap.yaml` `bind_set`): `fr.node.bind_set` answers INVALID_ARGS when the table with the new binding (its slot's old bytes excluded) would encode to a `BindingList` over 1400 B, so `bind_list` always returns the whole table; `binding_set` refuses the same (INVALID_ARGS), measured on the registry rows with the new binding in its slot, online or offline, next to the 16-slot limit. Handshake reconcile: clear stray slots first, then set the rows that are missing or differ; when `bind_list` cannot be read for any reason but CAPABILITY_UNSUPPORTED or DEVICE_OFFLINE, the registry wins blindly (clear every slot without a row, 255 when none, then set every row, stopping at the first push that does not go through; the next handshake starts over).
18. **RESOLVE classification** (05 §5.7 and §5.10): the hub's full sets always list every provisioned device, the asking node included, and every session gets the whole set. On the node a lone page 0 of 1 is classified by content, whatever RESOLVE is outstanding: one entry whose addr is not the node's own is a RESOLVE answer and merges; no entries means "unknown" and is ignored; neither touches a set being staged. Only a complete page set that lists the node itself replaces (and persists) the table. RESOLVE is throttled to once per second per addr over the last 4 addrs asked (the one asked longest ago reused when all 4 are in use).
19. **Same-run WELCOME floor** (refines 05 §5.8 "the node resets its hub entries on every WELCOME"): a WELCOME of the hub run the node already follows (same non-zero `hub_epoch`) only raises the BCAST window's floor to `bcast_base`, and the window never moves back, so seqs above the base that arrived first over the air or the other session stay recorded; a WELCOME of another run resets the window to its base. The unicast window, LATEST state and floor still reset on every WELCOME.
20. **Late send callbacks** (refines 5, the driver limits): the 100 ms guard fails the attempt but its callback stays owed; no other send (retry or next frame) goes out until that verdict arrives or 1 s after the send, when the callback is taken as lost. Verdicts are matched to sends by count and send order; a late verdict that arrives while a send is held only releases that send. `stats espnow` gains `guard?` and `lost?`.
21. **Node source windows** (05 §5.8): for a source new to the node (first heard, or evicted by the LRU), everything below its first ordinary frame is presumed received and is OLD, not DUP: never delivered, ACKed or answered from the cache (a sender whose earlier reliable frame was overtaken ends FAILED rather than getting a false ACK). For a newer epoch of a known source the window starts empty below the first ordinary frame of that boot, so frames of that boot it overtook are delivered.
22. **A fast frame with no path is BUSY** (07 §7.11, 03's MSG API, `Net::send_to_node`): when the ESP-NOW unicast and the TTL-1 broadcast were refused, there is no hub session, and the flooded unicast was refused or the flood rate spent, a fast frame is dropped (counted in `nodes.failed`) and the call answers BUSY; a reliable frame answers OK and is retried; a binding's frame is reported only through `node.binding_fired` (`target_status` BUSY). Not done: refunding the flood-rate token when the air send is refused.
23. **fr.node events are not bindable** (07 §7.11: "reacts to its own event" excludes fr.node events): fr.node's own events (port 0: `boot`, `binding_fired`) are emitted outside `Net::event`, where bindings run, so `binding_set` answers INVALID_ARGS for such a trigger; a stored row of that kind gets a `binding_unresolved` `hub.warning` when it is re-resolved.
24. **Binding args and MSG data as JSON text** (07 §7.11, 09 §9.4): the registry keeps the args or MSG data as the JSON text it was given and re-resolution parses that text, so a JSON string stays a string. MSG data `null` is the text `null` (payload `null`), distinct from no data (empty payload); `binding_list` shows `args: null` for both. A string given for args or data (CLI or REST) is always JSON text. The CLI renders a single broadcast as `broadcast <topic> seq N to K node(s)`.
